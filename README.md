# نظام إدارة جمعية العلوم الخيرية بعزبة الكوم (حضانة + كتاب)

نظام ويب متكامل (MERN Stack: MongoDB + Express + React + Node.js) لإدارة:
- 10 فروع (قابلة للزيادة)
- قسمين منفصلين بالكامل في كل فرع: **الحضانة** و **الكتاب**
- صفحة رئيسية (Landing Page) عامة قبل تسجيل الدخول
- الطلاب وتوزيعهم على المدرسين
- الموظفين ومديري الفروع
- الحضور والغياب
- الاختبارات الأسبوعية والشهرية
- **تقييم الطلاب** اليومي/الأسبوعي/الشهري (يسجّله المدرس)
- مسابقات الموظفين
- **طلبات الإجازة** للموظفين (بموافقة مدير الفرع أو الأدمن)
- المدفوعات (رسوم الطلاب) والمصروفات
- الرواتب
- **لوحة إعدادات** للأدمن الرئيسي لتغيير الشعار وصورة الصفحة الرئيسية ورقم واتساب التواصل والنصوص

## نظام الصلاحيات

| الدور | الصلاحيات |
|---|---|
| **أدمن رئيسي (super_admin)** | كل الصلاحيات على كل الفروع: إنشاء/حذف فروع، إنشاء مديري فروع، رؤية كل البيانات والتقارير |
| **مدير فرع (branch_manager)** | صلاحيات كاملة داخل فرعه فقط (طلاب، موظفين، حضور، مدفوعات، مصروفات، رواتب، اختبارات، مسابقات) — لا يقدر يشوف فروع تانية ولا ينشئ/يحذف فروع |
| **موظف (employee)** | يشوف طلابه (لو مدرس) ويسجل حضور/نتائج اختبارات، ويشوف راتبه هو بس |

## خطوات التشغيل

### 1) تشغيل الباك اند (Backend)

```bash
cd backend
npm install
cp .env.example .env
```

افتح ملف `.env` وعدّل القيم:
- `MONGO_URI`: رابط قاعدة البيانات (لو شغال MongoDB محليًا سيبها زي ما هي، أو حط رابط Atlas بتاعك)
- `JWT_SECRET`: غيّرها لأي نص عشوائي طويل وسري
- `SUPER_ADMIN_USERNAME` و `SUPER_ADMIN_PASSWORD`: بيانات دخول الأدمن الرئيسي اللي هتتنشئ

بعد كده، شغّل أمر التهيئة (يعمل الأدمن الرئيسي + 10 فروع تجريبية):

```bash
npm run seed
```

هيطبعلك في التيرمينال اسم المستخدم وكلمة المرور بتاعة الأدمن الرئيسي.

بعد كده شغّل السيرفر:

```bash
npm run dev
```

السيرفر هيشتغل على: `http://localhost:5000`

### 2) تشغيل الفرونت اند (Frontend)

في تيرمينال تاني:

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

هيفتحلك على: `http://localhost:5173`

سجّل دخول بالبيانات اللي طلعتلك من أمر `npm run seed`.

## أول خطوات بعد الدخول كأدمن رئيسي

1. روح لصفحة **"الفروع"** وعدّل أسماء الـ10 فروع لأسمائها الحقيقية (أو أضف/احذف فروع)
2. روح لصفحة **"الموظفون"** وأنشئ حساب **مدير فرع** لكل فرع
3. مدير الفرع بعد كده يقدر يدخل بحسابه وينشئ الموظفين (المدرسين) بتوع فرعه
4. ابدأ تسجيل الطلاب من صفحة **"الطلاب"** ووزّعهم على المدرسين

## هيكل المشروع

```
bilal-mern/
├── backend/
│   ├── config/db.js            # الاتصال بقاعدة البيانات
│   ├── models/                 # نماذج البيانات (User, Branch, Student, ...)
│   ├── middleware/auth.js      # التوثيق والصلاحيات
│   ├── routes/                 # مسارات الـ API
│   ├── utils/seed.js           # إنشاء الأدمن الرئيسي والفروع التجريبية
│   └── server.js               # نقطة تشغيل السيرفر
└── frontend/
    ├── src/
    │   ├── api/axios.js        # إعداد الاتصال بالـ API
    │   ├── context/AuthContext.jsx
    │   ├── components/         # مكونات مشتركة (القائمة الجانبية، النوافذ، ...)
    │   └── pages/               # كل صفحات النظام
    └── index.html
```

## نشر المشروع على سيرفر (لاحقًا)

- **الباك اند**: يمكن نشره على Render أو Railway أو أي VPS، مع ضبط `MONGO_URI` على قاعدة بيانات Atlas
- **الفرونت اند**: `npm run build` بينتج مجلد `dist` جاهز للنشر على Vercel أو Netlify أو أي استضافة ستاتيك، مع ضبط `VITE_API_URL` على رابط الباك اند بعد النشر

## الصفحة الرئيسية (Landing Page) وإعدادات المظهر

- الرابط `/` يعرض صفحة رئيسية عامة (بدون تسجيل دخول)، والدخول للنظام من زر "تسجيل الدخول" أو `/login`
- الأدمن الرئيسي يقدر من صفحة **"إعدادات الموقع"** (`/settings`) يغيّر:
  - شعار الجمعية (رفع صورة جديدة)
  - صورة الصفحة الرئيسية
  - اسم الجمعية والوصف والنبذة
  - رقم واتساب التواصل (يظهر كأيقونة عائمة في كل الصفحات)
- الصور المرفوعة بتتخزن في مجلد `backend/uploads` وتتقدَّم عن طريق السيرفر نفسه — **لازم تعمل نسخة احتياطية من المجلد ده لو هتنقل السيرفر**

## طلبات الإجازة والتقييمات

- أي موظف أو مدير فرع يقدر يقدّم طلب إجازة من صفحة **"طلبات الإجازة"**
- الموافقة أو الرفض بتتم من **مدير الفرع بتاع الموظف أو الأدمن الرئيسي**
- المدرسين يقدروا يسجّلوا **تقييم** لكل طالب (يومي/أسبوعي/شهري) من صفحة **"تقييم الطلاب"** يشمل: تقييم عام + حفظ + سلوك + مشاركة

## ملاحظات مهمة

- كل البيانات (الطلاب، المدفوعات، الرواتب...) مرتبطة بفرع معين، فمدير الفرع مش هيقدر يشوف أو يعدل بيانات فرع تاني حتى لو حاول من الـ API مباشرة (الحماية موجودة في الباك اند نفسه مش بس في الواجهة)
- **الموظف (المدرس)** في لوحة التحكم بيشوف بس عدد طلابه هو المتوزعين عليه (حسب قسمه: حضانة أو كتاب)، ومش بيشوف إجمالي عدد الطلاب أو الموظفين في الفرع كله
- قسم الحضانة وقسم الكتاب منفصلين بالكامل في البيانات (كل طالب له `department` محدد: `nursery` أو `quran`)
- ممكن تضيف المزيد من الفروع أو الحقول لاحقًا بسهولة من خلال تعديل الـ models في الباك اند
